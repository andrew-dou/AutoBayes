# Comparing records from the same target

New fit records contain model.target_identity with schema autobayes-target-v1 and a SHA256 digest frozen at model construction. The digest includes the effective fitted response/design/trials, row order, group coding, category references/levels, canonical formula, effective centering, resolved priors and family parameters. It excludes sampler backend, seed and runtime. Only the digest is exported; raw rows are not added to the record.

Numerics are normalized to finite float64 hexadecimal strings, signed zero is normalized, and array shapes and ordering are retained. Integer and float representations of the same float64 value match; this reflects the pinned float64 computational model, not arbitrary-precision data identity. String labels preserve exact text. Equivalent models expressed differently may conservatively hash differently. For binomial models, zero-trial rows already removed before design construction are excluded from target identity; their dropped-row provenance remains in the record.

compare_records(a, b) now requires matching current identities before evaluating mean agreement. Older records remain readable but cannot establish their fitted inputs from summary metadata. Recreate records only when the retained fit carries a valid captured binding to the original built model; merely supplying a model is not provenance. See [fit binding](fit-binding.md). Otherwise an explicit compare_records(a, b, allow_legacy=True) allows the historical metadata-only comparison and returns identity_status="unverified_legacy"; format_comparison prints a warning. A missing identity is never manufactured from old metadata. Invalid schemas/digests or differing current identities are refused even with that opt-in.

This is a digest of the built target specification, not an authenticity signature, a hash of arbitrary PyMC graph edits or proof of sampling correctness. Direct graph/configuration mutation after construction is unsupported; rebuild a model for a changed target. Caller-frame or exposed model.data edits do not rewrite the saved identity. The identity property returns a defensive copy. A matching identity says nothing about convergence, posterior calibration, or speed.
